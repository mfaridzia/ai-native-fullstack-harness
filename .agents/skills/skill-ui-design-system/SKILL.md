# Frontend Design Orchestrator

Apply the frontend design routing in root `AGENTS.md` and `WORKFLOW.md`.

1. Establish scope from the approved PRD. Do not begin production UI before required PRD and architecture approvals.
2. Use Impeccable as the default design workflow. If `PRODUCT.md` is missing before new visual work, run its `init` flow using approved specs and repository evidence, then confirm material gaps with the user.
3. Classify the target surface:
   - Operate or ordinary Read: Impeccable only.
   - Persuade or Experience marketing: Impeccable captures missing product context, Taste owns the single art-direction round, and Impeccable returns for constraints and finish review. Treat the approved Taste direction as pinned input; do not start a competing Impeccable direction round.
4. Use Emil's specialist skills only for purposeful motion after layout and visual direction are settled.
   - Prefer Emil `animate` over Impeccable `animate`; Impeccable may audit the result but does not create a second motion direction.
5. Preserve `DESIGN.md` and incumbent visual evidence. A missing file alone is not permission to redesign.
6. Require human direction approval before building a new or replacement visual world.
7. At finish, inspect the actual rendered UI, run relevant critique/audit/polish and motion review, then create or update `DESIGN.md` only for durable approved decisions.

Do not prescribe glassmorphism, bento grids, fonts, colors, fixed hover scaling, or `transition-all` as defaults.
